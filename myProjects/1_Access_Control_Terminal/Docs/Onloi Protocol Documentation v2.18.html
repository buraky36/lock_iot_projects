Sürüm Notları

v2.18 (21.10.2026)

  • SET_CLOUD_CONFIG (0x06). MQTT host/port/TLS, kullanıcı, şifre, deviceSecret ve sessionEpoch BLE ile NVS'e yazılır. Firmware'de derlenmiş URL/IP yoktur.
  • Cihaz HTTPS claim yok. POST /devices/claim ve BLE PROVISION (0x02) cihaz akışından çıktı. Onloi Cloud'da App POST /devices/{id}/runtime-config ile credential alır; BYOC'ta kullanıcı broker bilgilerini App'e girer.
  • Wi-Fi sonrası doğrudan MQTT. CONNECT_WIFI başarısından sonra cihaz NVS'teki broker'a bağlanır ve REGISTRATION yayınlar.
  • KEX_INIT kilide zorunlu değil. SET_CLOUD_CONFIG ve CONNECT_WIFI düz GATT ile gider (mevcut Wi-Fi şifresi modeli). Gateway onboarding ECDH ayrı kalır.
  • WIFI_RESET cloud config'i korur; SERVER_DISCONNECT / factory reset NVS cloud config'i siler.

v2.17 (03.08.2026)

  • localId alanı 3 byte oldu. Protokoldeki tüm localId alanları artık sabit 3 byte.
  • OFFLINE_LOG_BATCH (0x35) v2.12 sabit 13 byte kaydına döndü.

BLE Keşif — Cihaz Ekle

1 BLE Tarama — Cihazları Listele BLE

Kullanıcı "Cihaz Ekle"ye basar. Mobil Bluetooth taraması başlatır.

Mobil uygulama standart BLE taraması başlatır. Bu aşamada Onloi binary protokolü henüz başlamaz — yalnızca BLE'nin yerleşik reklam mekanizması kullanılır. deviceCode bu reklam paketlerinden okunur; HANDSHAKE beklenmez.

Nasıl çalışır?

Cihaz (peripheral) ve telefon (central) arasındaki iletişim bu aşamada tamamen standart BLE kurallarına göre ilerler. Onloi uygulaması cihaza özel bir istek göndermez; yalnızca startScan() ile taramayı başlatır. Gerisini telefonun BLE stack'i halleder.

  Kilit (firmware)                         Telefon (Onloi app)
  ─────────────────                        ────────────────────

  [1] Advertising Packet ──────────────────►  Sürekli, kendi kendine yayınlanır.
      (UUID: 6E400001-B5A3-F393-E0A9-E50E24DCCA9E)                  App olmasa bile yakındaki tarayıcılar alabilir.

  [2]         ◄──── SCAN_REQ ──────────────  App tarama başlatınca OS otomatik gönderir.
              (BLE standart — Onloi frame değil)

  [3] Scan Response Packet ────────────────►  Firmware'de hazır tutulan cevap paketi.
      (Local Name + Service Data)             App'in özel isteğine değil, SCAN_REQ'ye yanıt.
BLE reklam alanı en fazla 31 byte olduğu için firmware veriyi iki pakete böler: UUID ana reklamda, isim ve deviceCode Scan Response'ta. Bu yüzden mobil uygulama aktif tarama kullanmalıdır — aksi halde deviceCode gelmeyebilir.
// iOS — aktif tarama (Scan Response almak için gerekli)
centralManager.scanForPeripherals(
    withServices: [CBUUID(string: "6E400001-B5A3-F393-E0A9-E50E24DCCA9E")],
    options: [CBCentralManagerScanOptionAllowDuplicatesKey: true])

// Android
scanner.startScan(listOf(ScanFilter.Builder()
    .setServiceUuid(ParcelUuid.fromString("6E400001-B5A3-F393-E0A9-E50E24DCCA9E"))
    .build()), settings, callback)

2 BLE Bağlantı — GATT Keşfi BLE

Kullanıcı listeden bir cihaz seçer. BLE bağlantısı kurulur. Henüz Onloi frame yok.

Kullanıcı listeden bir cihaz seçer. Mobil BLE bağlantısı kurar ve GATT servisini keşfeder.

// Sırasıyla yapılacaklar:
1. connect(peripheralId)
2. discoverService("6E400001-B5A3-F393-E0A9-E50E24DCCA9E")
3. RX karakteristik: "6E400002-B5A3-F393-E0A9-E50E24DCCA9E"  → Mobil YAZAR (Onloi'ye giden veriler)
4. TX karakteristik: "6E400003-B5A3-F393-E0A9-E50E24DCCA9E"  → Mobil OKUR (notify aç, cihazdan gelen veriler)
5. TX karakteristiğine SUBSCRIBE (notify/indicate enable)
Bağlantı kurulunca bir sonraki adımda Onloi binary protokolü başlar. Frame boyutu 20 byte'ı aşıyorsa 0x00 ayırıcı ile parçalanır.

5 Bulut Hedefi — Onloi veya Kendi Broker HTTPS

Kullanıcı App'te iki yoldan birini seçer. Firmware'de derlenmiş URL/IP yoktur; tüm broker bilgisi bir sonraki adımda BLE ile yazılır. Cihaz HTTPS claim atmaz.

Onloi Cloud (varsayılan): App, giriş yapmış kullanıcı için Onloi'den runtime credential ister. Cihaz yine Onloi broker'ına bağlanır; yönetim App'te kalır.
POST https://api.onloi.com/v1/devices/78356203936/runtime-config

}
Response 200 OK
{

    "host": "mqtt.api.onloi.com",
    "port": 8883,

Header: Authorization: Bearer <kullanıcı JWT> — bu isteği App atar, cihaz atmaz.
Kendi ortamım (BYOC): Kullanıcı App'e broker host, port, TLS, kullanıcı, şifre ve deviceSecret girer (veya kendi API'sinden yapıştırır). App Onloi'ye runtime-config sormaz. Cihaz yalnızca o broker ile konuşur; Onloi App bundan sonra setup-only kalır.

Firmware Güncelleme (OTA) — MQTT kontrol + HTTPS indirme

42 OTA — Mimari Özet MQTT + HTTPS

Firmware güncellemede iki kanal kullanılır: MQTT komut ve durumu taşır; firmware dosyası HTTPS ile indirilir. Güncellenecek birim firmwareTarget ile seçilir: ESP (0x01), STM (0x02), BLE-only alt cihaz (0x03).

Cihaz türü notu: Üç senaryo aynı OTA komut setini kullanır.
  • Yalnızca ESP: target 0x01. STM/BLE-sub yolları yok.
  • ESP + STM: kendi ESP’si 0x01; STM imajı 0x02 (ESP staging → UART).
  • Gateway + BLE-only sub: GW kendi FW’si 0x01. Alt cihaz Wi-Fi/HTTPS yapamıyorsa target 0x03: imajı GW indirir, BLE ile yazar. Alt cihazın kendi Wi-Fi’si varsa o cihaz kendi deviceId’si ile 0x01 kullanır; 0x03 değildir.
Desteklenmeyen target → TARGET_INVALID (0x04). Sunucu Product ID / deviceCode kataloğundan geçerli target’ı seçer.
Kurallar:
  1. Sunucu veya cihaz güncellemeyi MQTT ile başlatır (FIRMWARE_UPDATE / FIRMWARE_UPDATE_REQUEST).
  2. Sunucu imzalı HTTPS URL + sürüm, boyut, SHA-256, CRC32 meta bilgisini MQTT komutuyla gönderir.
  3. İndiren taraf (cihaz veya GW) dosyayı HTTPS ile alır; flash’a yazar; SHA-256 + CRC32 doğrular.
  4. 0x01 / 0x02 / 0x03: indirme + doğrulama sonrası cihaz/GW self-apply (ESP flash / STM UART / BLE aktarım).
  5. 0x03 için subDeviceId ve/veya subMac dolu olmalıdır (aşağıdaki seçim kuralı).
  6. Product ID / Hardware Revision uyuşmazsa red.
  7. İlerleme FIRMWARE_STATUS ile MQTT’den bildirilir.
