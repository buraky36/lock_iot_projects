1. Genel Mimari ve Bileşenler

Sistem dört bileşenden oluşur. Her biri farklı bir bağlantı/erişim kısıtına sahiptir ve bu kısıtlar, aşağıda tanımlanan güvenlik modelinin temel gerekçesidir.

  • Sunucu (Server/Backend) — Kimlik/yetkilendirme, cihaz–hesap eşleşmesi ve local key dağıtımının tek gerçek kaynağı (single source of truth). MQTT broker'ı barındırır/yönetir.
  • Gateway (GW) — Wi-Fi ile internete çıkan, sunucuyla MQTT üzerinden haberleşen köprü cihaz. Etrafındaki BLE alt cihazlarını tarar, bağlanır, GATT read/write/notify yapar. Kendisi de ilk kurulumda mobil app ile BLE üzerinden eşleştirilir (WiFi provisioning).
  • Alt Cihazlar (Lock / Sensor / vb.) — Sadece BLE ile çalışır, internete çıkamaz. GW üzerinden (relay) veya GW erişilemezse mobil app ile doğrudan BLE üzerinden yönetilir.
  • Mobil App — Normal akışta Sunucu → MQTT → GW → BLE yolunu kullanır. GW çevrimdışıysa ve alt cihaz menzildeyse, kullanıcı fark etmeden doğrudan BLE'ye geçer (şeffaf fallback).

1b. BLE İletişim/Güvenlik Yöntemleri — Karşılaştırma ve Seçim Gerekçesi

BLE'de iki taraf arasında veri alışverişini korumak için üç ana yaklaşım vardır. Aşağıda üçü de kısaca tanımlanır ve neden 3. yöntemin seçildiği gerekçelendirilir.

1. Native BLE Bonding / Pairing (SMP)

OS'un kendi Security Manager Protocol'ü ile bir Long Term Key (LTK) üretilip OS keystore'unda saklanır. Sonraki bağlantılar bu LTK ile otomatik şifrelenir.

  • Artı: Hazır, test edilmiş, ekstra kod gerektirmez.
  • Eksi: LTK OS keystore'unda kilitlidir (app erişemez, başka cihaza taşınamaz/paylaşılamaz); iOS/Android arasında davranış farkı vardır; sistem seviyesi pairing dialogları kullanıcı deneyimini bozar; bir cihazın aynı anda birden fazla "trusted" merkeze (GW + N telefon) bağlanması multi-bond slot yönetimi gerektirir ve bazı çip/stack'lerde sınırlıdır.

2. Şifresiz Düz BLE Bağlantısı (Plaintext GATT)

Pairing yok, şifreleme yok — tüm veri açık metin olarak GATT üzerinden akar.

  • Artı: En basit, hiç kriptografi gerektirmez.
  • Eksi: Menzildeki herhangi biri trafiği dinleyebilir ya da sahte komut enjekte edebilir — üretim ortamı için kabul edilemez.

3. Uygulama Katmanı (Application-Layer) Şifreleme — "Local Key" Modeli (seçilen yöntem)

Native BLE pairing/bonding hiç kullanılmaz. Bunun yerine cihaz ile client (GW veya telefon) arasında bir local key üretilip (ECDH ile) anlaşılır; tüm veri, düz (unbonded) bir GATT bağlantısı üzerinden AES ile uygulama katmanında şifrelenmiş biçimde taşınır. BLE'nin kendisi sadece bir taşıma kanalıdır.

Neden 3. yöntemi seçtik?

  • Aynı cihaza birden fazla yetkili taraf (GW + telefon(lar)) aynı anda erişebilmeli; key'in merkezi olarak sunucuda saklanıp dağıtılabilmesi gerekiyor — native bonding'de LTK'ya bu şekilde merkezi/paylaşılabilir erişim mümkün değil.
  • GW üzerinden eklenen bir cihaza, telefonun hiç fiziksel temas etmeden (sunucudan key alarak) erişebilmesi gerekiyor — bu sadece app-layer modelle mümkün; native bonding'de LTK'yı GW'den telefona "devretmek" teknik olarak yapılamaz.
  • iOS (CoreBluetooth) ve Android (BluetoothGatt) arasında native bonding API'leri farklı UX ve kısıtlamalara sahiptir; kendi protokolümüz iki platformda bire bir aynı davranışı garanti eder.
  • Key rotasyonu, çoklu kullanıcı paylaşımı (device sharing), uzaktan yetki iptali gibi ihtiyaçlar native BLE'nin sağladığı esneklikten fazlasını gerektiriyor; kendi şifreleme protokolümüz bunu doğal olarak destekler.

2. GW Kurulumu (Onboarding)

GW'nin ilk kurulumu, sistemdeki tek güvenlik modeli olan app-layer/local-key yaklaşımıyla yapılır — native BLE bonding hiç kullanılmaz. GW henüz Wi-Fi'ye bağlı olmadığından sunucudan bir local key çekemez; bu yüzden mobil app ile GW arasında geçici bir oturum anahtarı, o anki BLE bağlantısı üzerinden ephemeral ECDH ile türetilir.

1BLE Tarama — GW'yi BulBLE

Kullanıcı "Gateway Ekle"ye basar. Mobil, GW'nin advertising verisini arar.

GW, kurulum modundayken (henüz claim edilmemiş) kendine özel bir Service UUID ile advertise eder:

// iOS
centralManager.scanForPeripherals(withServices: [CBUUID(string: "6E400101-B5A3-F393-E0A9-E50E24DCCA9E")])

// Android
scanner.startScan(listOf(ScanFilter.Builder()
    .setServiceUuid(ParcelUuid.fromString("6E400101-B5A3-F393-E0A9-E50E24DCCA9E"))
    .build()), settings, callback)
Advertising payload'ındaki manufacturer data içinde GW'nin deviceCode'u (model kodu, örn. OKGWX1) açık (şifresiz) biçimde ve 1 byte'lık claimed flag'i bulunur (bkz. Bölüm 11.7 / Bölüm 13). deviceCode bir modele ait olduğu için (tek bir cihaza özel değildir) açıkta taşınması bir gizlilik sorunu oluşturmaz; mobil, bağlanmadan önce bu koddan GW'nin adını/görselini gösterebilir. GW için bu flag 0x00 (unclaimed) olduğu sürece listede görünür.
2BLE Bağlantı — GATT KeşfiBLE

Kullanıcı listeden GW'yi seçer. BLE bağlantısı kurulur — pairing/bonding YOK.

1. connect(peripheralId)
2. discoverService("6E400101-B5A3-F393-E0A9-E50E24DCCA9E")
3. RX: "6E400102-..." → Mobil YAZAR
4. TX: "6E400103-..." → Mobil OKUR (notify aç)
5. TX karakteristiğine SUBSCRIBE
Bağlantı düz (unbonded) bir GATT bağlantısıdır. Bir sonraki adımda uygulama katmanı (Onloi binary frame + ECDH) başlar.

İki taraf da artık sessionKey = HKDF-SHA256(X25519(myPriv, peerPub), salt=deviceId) hesaplar. Bu anahtar sadece bu BLE bağlantısı için geçerlidir ve WiFi kimlik bilgilerini şifrelemek dışında kullanılmaz.

Bu, ECDH'nin aktif MITM saldırılarına karşı zayıf noktasını (pasif dinlemeye karşı zaten güvenli) kapatır.
4GET_SSIDS / CONNECT_WIFI — Şifreli Wi-Fi KurulumuBLE Frame

Mobil, GW'nin gördüğü Wi-Fi ağlarını ister; kullanıcı birini seçer ve şifreyi girer. Artık PAYLOAD alanı düz metin değil, sessionKey ile AES-GCM şifrelidir.

Mobil → GW (RX) — CMD: GET_SSIDS 0x03

Bu isteği GW firmware'i atar; deviceId+deviceCode'u kullanıcı hesabına eşleyen bilgi (örn. kutudaki QR/seri no ile mobil'in önceden sunucuya bildirdiği "beklenen deviceId") sunucu tarafında zaten mevcuttur.

GW artık online. Kendisi için kalıcı bir local key üretir (tıpkı alt cihazlarda olduğu gibi) ve sunucuya senkronize eder. Bundan sonra GW ↔ App arasındaki (nadiren gereken) doğrudan BLE işlemleri bu kalıcı key ile şifrelenir; tekrar ECDH yapmaya gerek kalmaz.

Request Body (Authorization: Bearer <gatewayAuthToken>)
{
  "localKey": "<32 byte AES-256 key, base64>",
  "keyVersion": 1
}

Sunucu bu key'i gateways tablosunda deviceId ile ilişkilendirerek saklar. Mobil app, kullanıcı bu GW'ye erişim yetkisine sahip olduğunda bu key'i sunucudan çekebilir (bkz. Bölüm 6, /gateway/{device_id}/settings benzeri korumalı bir endpoint).

GW, aldığı kimlik bilgileriyle MQTT broker'a bağlanır ve LWT (Last Will and Testament) kaydını yapar.

3. Alt Cihaz Ekleme — GW Üzerinden

GW her zaman etrafını tarar ve gördüğü BLE cihazlarını scan_report ile sunucuya bildirir (temel tarama davranışı, aşağıda genişletilmiş haliyle). Kullanıcı bu listeden bir cihaz seçtiğinde GW, o cihaza bağlanıp local key exchange'i yapar.

1GW Taraması — scan_reportMQTT

GW, BLE advertising paketlerini dinler ve gördüğü her cihazı anlık olarak sunucuya raporlar. Alt cihazın manufacturer data'sı, GW'ninkiyle aynı formatta açık (şifresiz) bir deviceCode taşır (bkz. Bölüm 11.7) — bu sayede GW, cihaza hiç bağlanmadan (KEX_INIT yapmadan) sadece pasif dinlemeyle onun model kodunu okuyup raporlayabilir.

PUBLISH/gateway/99120583417/scan_report
{
  "mac": "11:22:33:44:55:66",
  "rssi": -58,
  "data": "0201061BFF4F4B4F4B3033313000...",
  "deviceCode": "OK0310",
  "is_onloi": true,
  "claimed": false
}
Yeni alan: deviceCode — GW, data içindeki ham manufacturer data'yı kendisi parse ederek (Bölüm 11.7'deki sabit offsetlerden) çıkarır ve ayrı bir alan olarak ekler; sunucunun/mobilin ham hex'i tekrar parse etmesine gerek kalmaz. Mobil app, deviceCode'u kendi katalogunda (model → isim/görsel eşlemesi) arayarak taranan listede bağlanmadan önce cihazın adını ve görselini gösterebilir — talep edilen davranış budur. is_onloi: manufacturer data'daki Onloi imzasından anlaşılır. claimed: aynı manufacturer data içindeki 1 byte'lık "bound" flag'inden okunur (bkz. Bölüm 10, Bölüm 13). Sunucu, claimed:true olan ve başka bir hesaba ait cihazları mobil'e listelemez — bu filtre hem SDK/app seviyesinde hem sunucu seviyesinde uygulanır (defence in depth).

Kullanıcı, sunucudan gelen (scan_report'tan türetilmiş) listeden bir cihaz seçer. Mobil, sunucuya "bu cihazı bu GW üzerinden claim et" isteği gönderir; sunucu bunu GW'ye MQTT ile iletir.

Yeni topic: /gateway/{device_id}/device_claim — GW'ye "şu MAC'i claim et" komutu verir. GW bu isteği aldığında Adım 3-5'i uygular.
3GW → Alt Cihaz BLE BağlantısıBLE

GW, hedef MAC'e BLE ile bağlanır ve Onloi GATT servisini keşfeder (bkz. Onloi Smart Lock Protocol Adım 1-2, birebir aynı).

GW için bu, mobil'in yaptığı taramayla aynı GATT keşif adımlarıdır — sadece taramayı/bağlantıyı ESP-IDF/NimBLE (veya benzeri) BLE central stack'i üzerinden GW firmware'i yapar.

13. Gömülü (Firmware) Taraf İçin Bağlantı ve Yetkilendirme Rehberi

Bu bölüm, alt cihazın (ve gerekirse GW'nin) firmware'ini yazan gömülü yazılım mühendisine hitap eder. Kod örnekleri ESP-IDF/NimBLE tarzı gerçekçi API isimleri kullanır; derlenebilir tam bir program değildir ama mantıksal akışı doğrudan projeye uyarlanabilecek netlikte yansıtır.

1Peer Context ve Durum MakinesiFirmware

"Soft-level eşleştirme" sonrası firmware ne yapmalı: Cihaz, GATT bağlantısı kurulduğunda gelen tarafın (GW mi, telefon mu, hiç tanınmayan biri mi olduğunu) BLE seviyesinde ayırt edemez — sadece uygulama seviyesi handshake mesajının (SESSION_INIT) doğru local key ile şifrelenip şifrelenmediğine bakarak karar verir. Durum makinesi: UNAUTHENTICATED → (geçerli SESSION_INIT alındı) → AUTHENTICATED → (komut/notify serbest).

Her bağlantı (connection handle) için bir peer_ctx_t tutulur — bu, aynı anda birden fazla bağlantı (GW + N telefon) yönetimini de çözer: her biri kendi state, session_key ve son SEQ'ini kendi struct'ında taşır.

typedef enum {
    PEER_STATE_UNAUTHENTICATED = 0,  /* Baglandi ama local key ile dogrulanmadi */
    PEER_STATE_AUTHENTICATED   = 1,  /* SESSION_INIT/KEX_INIT basarili, session_key hazir */
} peer_state_t;

typedef struct {
    uint16_t      conn_handle;       /* NimBLE baglanti tanitcisi */
    peer_state_t  state;
    uint8_t       peer_eph_pub[32];  /* Karsi tarafin X25519 public key'i */
    uint8_t       session_key[32];   /* HKDF cikisi -- sadece AUTHENTICATED'te gecerli */
    uint8_t       conn_nonce[8];
    uint16_t      last_seq;          /* Replay korumasi */
    int64_t       connected_at_ms;
    esp_timer_handle_t unauth_timer;
    bool          unauth_timer_armed;
} peer_ctx_t;

/* GW + N telefon ayni anda baglanabilir (Politika A, bkz. Bolum 10 Adim 4).
   Politika B (tek aktif baglanti) secilirse MAX_PEERS=1 yapip yeni istekleri
   STATUS_BUSY (0x06) ile reddetmek yeterlidir. */
#define MAX_PEERS 4
static peer_ctx_t s_peers[MAX_PEERS];
2GATT Connect/Disconnect — Peer Context Yaşam DöngüsüFirmware

Yeni bir GATT bağlantısı geldiğinde bir peer context ayrılır ve UNAUTHENTICATED olarak başlatılır; bağlantı koptuğunda context serbest bırakılır.

static peer_ctx_t *peer_ctx_alloc(uint16_t conn_handle) {
    for (int i = 0; i < MAX_PEERS; i++) {
        if (s_peers[i].conn_handle == 0) {
            memset(&s_peers[i], 0, sizeof(peer_ctx_t));
            s_peers[i].conn_handle = conn_handle;
            s_peers[i].state = PEER_STATE_UNAUTHENTICATED;
            s_peers[i].connected_at_ms = esp_timer_get_time() / 1000;
            return &s_peers[i];
        }
    }
    return NULL;  /* MAX_PEERS dolu -- yeni GATT connect STATUS_BUSY ile reddedilecek */
}

static void peer_ctx_free(uint16_t conn_handle) {
    for (int i = 0; i < MAX_PEERS; i++) {
        if (s_peers[i].conn_handle == conn_handle) {
            unauth_timeout_disarm(&s_peers[i]);
            memset(&s_peers[i], 0, sizeof(peer_ctx_t));
            break;
        }
    }
}

static int gap_event_handler(struct ble_gap_event *event, void *arg) {
    switch (event->type) {
    case BLE_GAP_EVENT_CONNECT:
        if (event->connect.status == 0) {
            uint16_t conn_handle = event->connect.conn_handle;
            peer_ctx_t *ctx = peer_ctx_alloc(conn_handle);
            if (!ctx) {
                ble_gap_terminate(conn_handle, BLE_ERR_REM_USER_CONN_TERM);
                break;
            }
            unauth_timeout_arm(ctx);   /* bkz. 13.7 */
        }
        break;
    case BLE_GAP_EVENT_DISCONNECT:
        peer_ctx_free(event->disconnect.conn.conn_handle);
        break;
    default:
        break;
    }
    return 0;
}
3SESSION_INIT İşlemeFirmware

GATT connect callback → bağlantı kaydı oluştur (state=UNAUTHENTICATED) → SESSION_INIT write geldiğinde local key ile doğrula → başarılıysa state=AUTHENTICATED yap ve ECDH'den türetilmiş session key'i bu bağlantı için sakla → bundan sonraki her notify/write işleminde bu session key kullanılır.

/* Gelen SESSION_INIT (0x70) REQUEST frame'ini isler.
   Cihaz karsi tarafin kim oldugunu (GW mi telefon mu) hic bilmez;
   sadece proof'un gecerli local_key ile uretilip uretilmedigine bakar. */
static void handle_session_init(peer_ctx_t *ctx, const onloi_frame_t *frame) {
    const uint8_t *peer_eph_pub = frame->payload;               /* [0:32]  */
    const uint8_t *conn_nonce   = frame->payload + 32;           /* [32:40] */
    const uint8_t *proof        = frame->payload + 40;           /* [40:56] */

    uint8_t hmac_input[32 + 8 + DEVICE_ID_LEN];
    uint8_t expected_proof[32];
    memcpy(hmac_input, peer_eph_pub, 32);
    memcpy(hmac_input + 32, conn_nonce, 8);
    memcpy(hmac_input + 40, g_device_id, DEVICE_ID_LEN);

    mbedtls_md_hmac(mbedtls_md_info_from_type(MBEDTLS_MD_SHA256),
                     g_local_key, sizeof(g_local_key),
                     hmac_input, sizeof(hmac_input), expected_proof);

    if (memcmp(proof, expected_proof, 16) != 0) {
        send_response(ctx, CMD_SESSION_INIT, STATUS_AUTH_FAILED, NULL, 0);
        return;   /* state UNAUTHENTICATED'te kalir -- 13.7'deki timer hala aktif */
    }

    /* Proof dogru: bu baglantiya ozel ephemeral X25519 anahtar ciftini uret,
       ECDH ile ortak secret'i hesapla, HKDF ile session_key turet. */
    uint8_t my_eph_priv[32], my_eph_pub[32], shared_secret[32];
    x25519_generate_keypair(my_eph_priv, my_eph_pub);
    x25519_scalarmult(shared_secret, my_eph_priv, peer_eph_pub);
    hkdf_sha256(conn_nonce, 8, shared_secret, 32,
                (const uint8_t *)"onloi-gw-session-v1", 20,
                ctx->session_key, 32);

    memcpy(ctx->peer_eph_pub, peer_eph_pub, 32);
    memcpy(ctx->conn_nonce, conn_nonce, 8);
    ctx->last_seq = frame->seq;
    ctx->state = PEER_STATE_AUTHENTICATED;
    unauth_timeout_disarm(ctx);

    uint8_t resp_payload[48];
    memcpy(resp_payload, my_eph_pub, 32);
    hmac_sha256_truncated(ctx->session_key, my_eph_pub, 32, conn_nonce, 8,
                           resp_payload + 32, 16);
    send_response(ctx, CMD_SESSION_INIT, STATUS_OK, resp_payload, sizeof(resp_payload));
}
4Notification/Indication Yayınlama KuralıFirmware

Cihaz, characteristic notify/indicate göndermeden önce, o bağlantının AUTHENTICATED state'te olup olmadığını kontrol etmelidir. UNAUTHENTICATED bir bağlantıya asla EVENT/notify gönderilmez — bu, henüz doğrulanmamış bir dinleyiciye bilgi sızdırmayı önler.

/* Her GATT notify/indicate yayinlamadan once cagrilir -- prensip:
   sadece AUTHENTICATED baglantilar EVENT alabilir. */
static bool peer_can_receive_notify(const peer_ctx_t *ctx) {
    return ctx != NULL && ctx->state == PEER_STATE_AUTHENTICATED;
}

void onloi_notify_event(uint8_t cmd, const uint8_t *plain_payload, size_t len) {
    for (int i = 0; i < MAX_PEERS; i++) {
        peer_ctx_t *ctx = &s_peers[i];
        if (!peer_can_receive_notify(ctx)) {
            continue;   /* UNAUTHENTICATED baglantilara asla EVENT gonderilmez */
        }
        uint8_t nonce[12], ciphertext[MAX_PAYLOAD], tag[16];
        derive_nonce(ctx->conn_nonce, ctx->last_seq + 1, nonce);
        aes_gcm_encrypt(ctx->session_key, nonce, plain_payload, len, ciphertext, tag);

        onloi_frame_t frame;
        build_frame(&frame, MSG_TYPE_EVENT, cmd, ++ctx->last_seq,
                    STATUS_OK, ciphertext, len, tag);
        gatt_send_notification(ctx->conn_handle, &frame);
    }
}
5Replay/Nonce KontrolüFirmware

Gelen her frame'in SEQ alanı, o peer context'te tutulan son SEQ'ten büyük olmalıdır; değilse frame reddedilir.

static bool seq_is_fresh(peer_ctx_t *ctx, uint16_t incoming_seq) {
    /* uint16 taşması (wraparound) için işaretli fark kullanılır */
    int16_t diff = (int16_t)(incoming_seq - ctx->last_seq);
    if (diff <= 0) {
        return false;   /* eski veya tekrarlanan SEQ -- STATUS_REPLAY_DETECTED */
    }
    ctx->last_seq = incoming_seq;
    return true;
}

/* Her gelen frame'in en basinda cagrilir. */
static int on_frame_received(peer_ctx_t *ctx, onloi_frame_t *frame) {
    if (ctx->state == PEER_STATE_AUTHENTICATED && !seq_is_fresh(ctx, frame->seq)) {
        send_response(ctx, frame->cmd, STATUS_REPLAY_DETECTED, NULL, 0);
        return -1;
    }
    return dispatch_frame(ctx, frame);
}
6Advertising DavranışıFirmware

Manufacturer data, sabit deviceCode (model kodu) ve cihazın claimed durumuna göre değişen 1 byte'lık bir "bound" flag'i taşır (bkz. Bölüm 11.7). deviceCode modele özel olduğu için açık taşınır; bu sayede mobil app/GW, cihaza bağlanmadan sadece pasif tarama ile onun model adını/görselini gösterebilir.

/* deviceCode modelin ROM'una gomulu sabit bir ASCII kod, ornegin "OK0310".
   claimed flag'i manufacturer data'nin son byte'ina yazilir. */
static void update_advertising_data(void) {
    uint8_t mfg_data[9] = {
        0x4F, 0x4B,                              /* "OK" -- Onloi imzasi */
        g_device_code[0], g_device_code[1],      /* deviceCode[0:6] -- acik, modele ozel */
        g_device_code[2], g_device_code[3],
        g_device_code[4], g_device_code[5],
        g_claimed ? 0x01 : 0x00,                 /* claimed flag */
    };

    struct ble_hs_adv_fields fields = {0};
    fields.mfg_data = mfg_data;
    fields.mfg_data_len = sizeof(mfg_data);
    fields.name = (uint8_t *)g_ble_device_name;
    fields.name_len = strlen(g_ble_device_name);
    fields.name_is_complete = 1;
    ble_gap_adv_set_fields(&fields);

    /* ESP-IDF/Bluedroid stack kullaniliyorsa muadili:
       esp_ble_gap_config_adv_data(&adv_data); */
}

/* CLAIM/UNCLAIM sonrasi cagrilir -- Bolum 10 Adim 5. */
void on_claim_state_changed(bool claimed) {
    g_claimed = claimed;
    update_advertising_data();
    ble_gap_adv_stop();
    ble_gap_adv_start(BLE_OWN_ADDR_PUBLIC, NULL, BLE_HS_FOREVER,
                       &adv_params, gap_event_handler, NULL);
}
7UNAUTHENTICATED Bağlantıların Timeout ile KesilmesiFirmware

Belirli bir süre (5 saniye) içinde geçerli SESSION_INIT/KEX_INIT gelmezse bağlantı firmware tarafından otomatik kesilir (DoS/boşta bağlantı önleme).

#define UNAUTH_TIMEOUT_MS 5000

static void unauth_timeout_cb(void *arg) {
    peer_ctx_t *ctx = (peer_ctx_t *)arg;
    if (ctx->state == PEER_STATE_UNAUTHENTICATED) {
        /* 5 saniyede gecerli SESSION_INIT/KEX_INIT gelmedi --
           DoS/bosta baglanti onleme amaciyla baglantiyi kes. */
        ble_gap_terminate(ctx->conn_handle, BLE_ERR_REM_USER_CONN_TERM);
    }
}

static void unauth_timeout_arm(peer_ctx_t *ctx) {
    const esp_timer_create_args_t args = {
        .callback = unauth_timeout_cb,
        .arg = ctx,
        .name = "onloi_unauth_to",
    };
    esp_timer_create(&args, &ctx->unauth_timer);
    esp_timer_start_once(ctx->unauth_timer, UNAUTH_TIMEOUT_MS * 1000);
    ctx->unauth_timer_armed = true;
}

static void unauth_timeout_disarm(peer_ctx_t *ctx) {
    if (ctx->unauth_timer_armed) {
        esp_timer_stop(ctx->unauth_timer);
        esp_timer_delete(ctx->unauth_timer);
        ctx->unauth_timer_armed = false;
    }
}
